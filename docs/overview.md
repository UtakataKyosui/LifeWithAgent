## 1. プロジェクト概要

### 1.1 目的

日々のタスクと習慣を、**声またはテキストで手軽に記録・確認できる**生活管理アプリケーションを開発する。AIアシスタントが自然言語を解釈し、記録や確認を代行する。

### 1.2 コンセプト

> 「話しかけるだけで、生活が記録される」

- 「牛乳を買うをタスクに追加して」「今日ストレッチやった」と話しかけるだけで記録できる
- アプリ操作の手間を減らし、記録の継続を支援する
- 将来はMCPで外部サービスと連携し、生活全体を支援するアシスタントへ発展させる

### 1.3 基本方針

| 方針 | 内容 |
|---|---|
| テキスト中心の設計 | AIへの入出力は常にテキストで行う。音声は入出力層で変換する |
| 低コスト運用 | リアルタイム音声APIは使わず、ターン制（STT → AI → TTS）を採用する |
| 段階的な拡張 | テキスト経路を完成させてから、音声・MCPを追加する |
| 安全な外部連携 | 外部サービスへの書き込みは、ユーザーの確認を必須とする |

## 2. スコープ

### 2.1 MVPの対象範囲

| 区分 | 内容 |
|---|---|

## 3. 技術選定

### 3.1 技術スタック一覧

| レイヤー | 採用技術 | 選定理由 |
|---|---|---|
| AIフレームワーク | **Mastra**（TypeScript） | Agent・Tools・Memory・MCPを統合的に扱える。Cloudflare向けデプロイヤーがある |
| 言語 | TypeScript | Mastraの標準言語。フロント・バックエンドで言語を統一できる |
| LLM | **Workers AI** | Cloudflare内で完結し、バインディング経由で低レイテンシに呼び出せる。無料枠がある |
| STT（音声→テキスト） | **Workers AI Whisper**（`@cf/openai/whisper-large-v3-turbo`） | 日本語精度と速度のバランスが良い。端末差なく同一の挙動を得られる |
| TTS（テキスト→音声） | **Web Speech Synthesis API**（ブラウザ標準） | APIコストが0円。MVPとして十分な品質 |
| データベース | **Cloudflare D1** | Workers環境で利用できるSQLite互換DB。Mastraのストレージアダプターがある |
| 外部連携 | **MCP**（`@mastra/mcp`） | 外部サービスとの連携を標準的な方式で追加できる |
| 実行・デプロイ環境 | **Cloudflare**（Pages指定 ※7.1参照） | AI・DB・ホスティングをCloudflareで一元管理できる |
| フロントエンド | 静的HTML/JS（Mastraと同一デプロイ） | ビルド不要でシンプル。1デプロイで完結する |

### 3.2 LLMモデル

| 用途 | 候補モデル | 備考 |
|---|---|---|
| Agent（会話・ツール呼び出し） | `@cf/meta/llama-3.3-70b-instruct-fp8-fast` | 第一候補。日本語品質とツール呼び出しの安定性を初期段階で検証する |
| 代替候補 | Workers AI上のツール呼び出し対応モデル（Qwen系など） | 検証結果が不十分な場合に比較する |

> **検証方針**：開発の最初の段階で「日本語でのツール呼び出しが安定するか」を検証する。不十分な場合は別モデルを検討する。モデル指定は1箇所で切り替えられる設計とする。

### 3.3 採用しなかった技術と理由

| 技術 | 不採用理由 |
|---|---|
| リアルタイム音声API（OpenAI Realtime等） | 分単位の課金でコストが高い。短い発話中心の用途に見合わない |
| ブラウザの `SpeechRecognition` API | Safari/iOSでの対応が不安定で、端末間の挙動差が大きい |
| 外部LLM（OpenAI / Anthropic等） | Workers AIで完結させる方針のため。ただし品質面の代替手段として残す |

## 4. システム構成

### 4.1 アーキテクチャ全体図

```text
┌──────────────────────────────────────────────┐
│ Cloudflare（1デプロイに統合）                  │
│                                              │
│ [フロントエンド]（静的アセット）                 │
│   ・チャットUI                                │
│   ・Push to Talk 録音                         │
│   ・文字起こし結果の確認・編集                   │
│   ・speechSynthesis による読み上げ             │
│                                              │
│ [API]                                        │
│   POST /api/voice/transcribe → Whisper(STT)  │
│   POST /api/agents/.../generate → Agent      │
│                                              │
│ [Mastra]                                     │
│   Agent: 生活管理アシスタント                   │
│    ├─ 自前Tools: タスク管理・習慣管理            │
│    └─ MCP Tools: 外部サービス連携               │
│   Memory: 会話履歴                             │
└───────┬───────────────────┬──────────────────┘
        │                   │
   ┌────▼────┐       ┌──────▼──────┐
   │   D1    │       │ Workers AI   │
   │ tasks   │       │ ・LLM         │
   │ habits  │       │ ・Whisper     │
   │ logs    │       └──────────────┘
   └─────────┘
```

### 4.2 処理フロー

#### 音声入力の場合

```text
1. ユーザーが録音ボタンを押して話す（Push to Talk）
2. ボタンを離すと録音終了、音声ファイルをSTT APIへ送信
3. Workers AI Whisperで文字起こし
4. 文字起こし結果を入力欄に表示（ユーザーが確認・修正可能）
5. ユーザーが送信
6. Mastra Agentが解釈し、必要なToolを実行
7. 応答テキストを画面に表示し、音声で読み上げ
```

#### テキスト入力の場合

上記の手順5から同じ処理となる。**音声とテキストで同一のAgent・Tools・Memoryを使用する。**

## 5. 機能要件

### 5.1 タスク管理

| ID | 機能 | 内容 | 発話例 |
|---|---|---|---|
| FR-T01 | タスク追加 | タイトルと期限（任意）を指定してタスクを登録する | 「明日までに牛乳を買うを追加して」 |
| FR-T02 | タスク一覧 | 未完了タスクを期限順に取得する | 「今やることを教えて」 |
| FR-T03 | タスク完了 | タイトルの部分一致でタスクを特定し、完了にする | 「牛乳買ったよ」 |
| FR-T04 | 期限の自然言語解釈 | 「明日」「今週金曜」などを日付に変換する | 「金曜までに書類を出す」 |

### 5.2 習慣管理

| ID | 機能 | 内容 | 発話例 |
|---|---|---|---|
| FR-H01 | 習慣登録 | 習慣名と頻度（毎日／毎週）を登録する | 「毎日ストレッチする習慣を追加して」 |
| FR-H02 | 達成記録 | 習慣名の部分一致で特定し、当日の達成を記録する | 「ストレッチやった」 |
| FR-H03 | 重複記録の防止 | 同じ習慣を同じ日に二重記録しない | 「ストレッチやった」（2回目） |
| FR-H04 | 達成状況確認 | 今日の達成状況と連続日数を返す | 「今日の習慣どうなってる？」 |

### 5.3 サマリー

| ID | 機能 | 内容 | 発話例 |
|---|---|---|---|
| FR-S01 | 週次サマリー | 今週のタスク完了数と習慣達成率を返す | 「今週どうだった？」 |

### 5.4 音声入出力

| ID | 機能 | 内容 |
|---|---|---|
| FR-V01 | Push to Talk録音 | ボタン押下中に録音し、離した時点で録音を終了する |
| FR-V02 | 文字起こし | 録音した音声をWhisperでテキスト化する |
| FR-V03 | 文字起こし結果の編集 | 送信前に文字起こし結果を確認・修正できる |
| FR-V04 | 音声読み上げ | Agentの応答をブラウザのTTSで読み上げる |
| FR-V05 | 読み上げのON/OFF | 読み上げの有効・無効を切り替えられる |

### 5.5 AIアシスタント

| ID | 機能 | 内容 |
|---|---|---|
| FR-A01 | 自然言語による操作 | 発話・入力内容から意図を判定し、適切なToolを実行する |
| FR-A02 | 音声向けの応答 | 応答は1〜3文の簡潔な日本語とし、マークダウン記号を使わない |
| FR-A03 | 聞き返し | 対象が複数該当・該当なしの場合は、ユーザーに確認する |
| FR-A04 | 会話履歴の保持 | Memoryにより会話の文脈を保持する（「それも完了にして」等に対応） |

### 5.6 MCP連携

| ID | 機能 | 内容 |
|---|---|---|
| FR-M01 | SSE型MCP対応 | URL指定でリモートMCPサーバーに接続し、ツールを利用できる |
| FR-M02 | npx型MCP対応 | コマンド指定でstdio型MCPサーバーを起動し、ツールを利用できる（ローカル環境のみ） |
| FR-M03 | 環境による切り替え | 実行環境に応じて、利用可能なMCPサーバーのみを読み込む |
| FR-M04 | MCP未設定時の動作 | MCPサーバーが0件でもアプリが正常に動作する |
| FR-M05 | 書き込み前の確認 | MCPツールによる外部サービスへの書き込み前に、ユーザーの確認を得る |

#### MCPの環境別対応

| 実行環境 | SSE型 | npx型 |
|---|---|---|
| ローカル開発（`mastra dev` / Node.js） | ○ | ○ |
| 本番（Cloudflare） | ○ | ×（ランタイムの制約により不可） |

#### MCPツールの権限レベル

| レベル | 対象操作の例 | 実行ルール |
|---|---|---|
| 読み取り | 予定の確認、タスク検索 | 自動実行可 |
| 書き込み | 予定の作成、タスク追加 | ユーザー確認後に実行 |
| 重大操作 | データ削除、送信、決済 | 明示的な再確認を必須とする |

## 6. 非機能要件

| 分類 | 要件 |
|---|---|
| 性能 | 音声送信から応答表示まで、目安として数秒以内を目指す |
| 録音長 | 1回の発話は最大30秒程度を想定する（長時間録音は対象外） |
| コスト | Workers AIの無料枠内での運用を目標とする |
| 対応ブラウザ | Chrome、Safari（iOS含む）、Edge の最新版 |
| 音声形式 | `audio/webm`を基本とし、iOS Safari向けに`audio/mp4`にフォールバックする |
| タイムゾーン | 日付の判定は **日本時間（Asia/Tokyo）** を基準とする（習慣の「今日」の判定を誤らないため） |
| セキュリティ | 認証情報（APIキー・MCPトークン）はシークレットとして管理し、会話履歴・Memory・ログ・プロンプトに含めない |
| プライバシー | 音声は録音終了時のみ送信し、常時ストリーミングしない。音声ファイルはサーバーに保存しない |
| 保守性 | LLMモデルの指定は1箇所に集約し、容易に切り替えられるようにする |

## 7. 制約事項・リスク

### 7.1 デプロイ先について（要決定）

要件では **Cloudflare Pages** が指定されている。一方で、以下の理由から **Cloudflare Workers（静的アセット配信）** の方が適している可能性がある。

- Mastraの公式デプロイヤー（`@mastra/deployer-cloudflare`）がWorkersを対象としている
- Cloudflareが新規のフルスタックアプリにWorkersを推奨している
- フロントエンドとMastraを1デプロイに統合しやすい

設計・実装内容はどちらでもほぼ共通のため、初期構築時に最終決定する。

### 7.2 リスク一覧

| リスク | 影響 | 対策 |
|---|---|---|
| Workers AIでのツール呼び出しが不安定 | Agentが正しく記録できない | 開発初期に検証する。モデル切り替えを容易にしておく |
| Workers AIの日本語品質 | 応答が不自然になる | 初期検証で確認し、instructionsで調整する |
| 音声の誤認識 | 誤ったデータが記録される | 文字起こし結果を送信前に編集可能にする。外部書き込み前は確認を挟む |
| Workersの実行制約（CPU時間・Node.js API） | 一部ライブラリが動作しない | `nodejs_compat`フラグを有効化。本番ではnpx型MCPを使わない |
| iOSのTTS音声品質 | 読み上げの聞き心地が悪い | MVPでは許容し、将来サーバーサイドTTSへの切り替えを検討する |
| MastraのAPI変更 | 実装方法が変わる | バージョンを固定し、実装時に公式ドキュメントを確認する |
| MCPツール数の増加 | ツール選択精度の低下・コスト増 | 必要なツールのみをAgentに渡す |

| カラム | 型 | 説明 |

## 12. 用語集
